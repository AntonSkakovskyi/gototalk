# Як працювати з Claude Code над GoToTalk (для Антона)

## Головна ідея: модель перемикається сама

Не треба вручну запускати Opus для розбору, а потім перемикати на Sonnet. У `.claude/settings.json` стоїть модель `opusplan`:
- у **plan mode** (Shift+Tab) працює **Opus**: розбирається в коді, проєктує, пише план;
- коли ви **погоджуєте план** і виходите з plan mode, далі реалізує **Sonnet** за цим планом.

Сабагент `reviewer` завжди працює на Sonnet (вказано в його файлі).

Opus витрачає ліміт Pro помітно швидше, тому plan mode — для рівня **сценарію або складної задачі**, а не для кожної дрібниці.

## Ритм одного сценарію

1. **План (Opus, один раз на сценарій).** Plan mode → «Прочитай `docs/specs/NN-*.md`, склади план і розбий на задачі в `docs/specs/NN-*.tasks.md`». Перечитайте план, поправте, погодьте. Для великого сценарію (04, діалог) можна замість цього запустити `/feature-dev` з посиланням на spec: він сам пройде дослідження коду, архітектуру з кількома варіантами, реалізацію й рев'ю, зупиняючись на ваших погодженнях.
2. **Гілка.** «Створи гілку `feat/NN-name`».
3. **Задачі (Sonnet, по одній).** `/clear` → «Виконай наступну невиконану задачу з `docs/specs/NN-*.tasks.md` за TDD». Claude пише тест, код, проганяє перевірки. Stop-хук не відпустить його з червоними тестами.
4. **Рев'ю й коміт.** «Запусти reviewer на поточних змінах, виправ блокери, закоміть і відміть задачу в tasks.md». Далі `/clear` і наступна задача.
5. **Кінець сценарію.** Ви робите `git push` і відкриваєте PR → CI → `/code-review` → злиття в `main`.

Ваша роль на кроці 3 — відповідати на питання й дивитися результат на телефоні, а не диктувати кожен крок.

## Чому `/clear` між задачами

План і стан живуть у файлах (`tasks.md`, код, git), а не в розмові. Свіжа сесія на кожну задачу дешевша за токенами, і Claude не плутається в старому контексті. Перед довгою перервою всередині задачі — `/compact`.

## Інші способи і чому не вони

| Спосіб | Що це | Для нас |
|---|---|---|
| Ручне перемикання `/model opus` ↔ `/model sonnet` | Те саме, що opusplan, але вручну | Не потрібно, opusplan робить це сам |
| `/feature-dev` | Один запуск проводить фічу через 7 фаз з агентами-дослідником, архітектором і рев'юером | Добре для великих сценаріїв (03, 04); дорожчий за звичайний план |
| Сабагент-планувальник на Opus | Окремий агент лише для планування | Дублює opusplan |
| Ralph-цикл / `/loop` | Агент сам крутиться, доки не скаже «готово» | На Pro швидко з'їдає ліміт; на Windows офіційний плагін погано працює. Лише для механічних задач з обмеженням ітерацій |
| Agent teams, паралельні агенти | Кілька сесій одночасно | Множить витрату токенів у рази; агенти конфліктують на тих самих файлах (схема, DTO) |

## Ліміти Pro: на що дивитись

- `/usage` раз на день. Якщо великий шматок іде на сабагентів, MCP чи плагіни — сигнал прибрати зайве.
- 5-годинне вікно закінчилось — перерва або робота без Claude (перевірка на телефоні, тексти для лабораторних).
- Ознаки марної витрати: Claude кілька разів поспіль повторює ту саму помилку (зупиніть, `/clear`, уточніть задачу); роздутий CLAUDE.md; Opus на рутинних CRUD-задачах.
- Тижневий ліміт закінчується два тижні поспіль — тоді думати про інший план, а не ускладнювати процес.

## Корисні команди в сесії

`Shift+Tab` — режими (звичайний / auto-accept / plan) · `/clear` — нова розмова · `/compact` — стиснути контекст · `/usage` — ліміти · `/model` — модель · `/agents` — сабагенти · `/mcp` — MCP-сервери · `/code-review` — рев'ю PR · `/feature-dev` — фіча за фазами · `/db-migration` — зміна схеми · `Esc` — зупинити Claude · `Esc Esc` — повернутись до попереднього повідомлення.
