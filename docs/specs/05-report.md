# 05. Сценарій 4: звіт після сесії

Гілка: `feat/05-report`. Таблиці: `session_reports`, `mistakes`, `words`, `utterances`.

Вимоги (лаба 6): UR-7, UR-8, FR-8, FR-9, FR-11, FR-12, FR-14.

Назва кожного тесту починається з ID тест-кейса, наприклад `[TC-05-03] ...`; перелік тест-кейсів у `docs/specs/test-cases.md`.

## Поведінка

- Після завершення сесії генерується звіт (`LanguageModelPort.summarizeSession(...)`) і зберігається в `session_reports`. Помилки вже проаналізовані під час діалогу, тож звіт будується швидко.
- Коротке самарі (екран за замовчуванням):
  - 2–3 речення: що вийшло добре і на чому зосередитись;
  - топ-3 категорії помилок у цій сесії з кількістю;
  - тривалість і кількість відповідей.
- Глибокий розбір (кнопка «Детально»): усі репліки з підсвіченими помилками (той самий компонент, що в діалозі), згруповані за категоріями; посилання на теорію з `theory_links` для категорії, якщо є; кнопка «Це не помилка».
- Позначки слів: список нових слів сесії (підказки + слова, які модель запропонувала в кращих формулюваннях) з трьома кнопками на кожному: «знав» (passive), «частково» (partial), «не знав» (new). Одна позначка — один дотик; можна змінити.
- Звіт доступний пізніше зі списку сесій.

## API

`POST /api/sessions/:id/finish` · `GET /api/sessions/:id/report` · `PATCH /api/words/:id` (стан)

## Готово, коли

- Unit: агрегація помилок за категоріями без `is_false`; побудова списку слів сесії без дублікатів (`lower(lemma)`).
- Інтеграційні: finish → report створено; повторний finish не створює другий звіт.
- e2e: завершити сесію з діалогу → самарі → «Детально» → позначити 3 слова → повернутися зі списку сесій → позначки збережені.
- Промпт: `packages/prompts/session-summary.v1.md`.
