# 03. Сценарій 2: старт сесії

Гілка: `feat/03-session-start`. Таблиці: `sessions`, `utterances` (перше питання), `mistake_patterns`, `profiles`, `goals`.

## Поведінка

- Головний екран: кнопка «Почати сесію» (запуск в один дотик) і список останніх сесій.
- Після натискання система пропонує тему й 5 питань:
  - вхід для планувальника: рівень, сцени, активні цілі, топ-3 патерни помилок;
  - генерує `LanguageModelPort.planSession(...)`; Fake-адаптер повертає детерміновану тему з набору за сценою;
  - якщо патерни є, хоча б одне питання має провокувати найчастіший патерн (наприклад, розповідь у минулому часі для `verb_tense`). Це правило в промпті, Fake-адаптер його імітує.
- Користувач може: прийняти тему, попросити іншу (до 3 разів) або ввести свою (`topic_source = custom`; тоді питання генеруються під неї).
- Перемикач режиму фідбеку: «Після кожної відповіді» (`immediate`) / «В кінці» (`deferred`). Типовий — `immediate`.
- Старт створює `sessions` (`status = active`) і першу репліку `assistant` з першим питанням. Решта питань плану зберігаються в сесії (вирішити в плані: окреме поле JSONB у `sessions` через нову міграцію чи наперед створені репліки; запропонувати варіант і спитати).

## API

`POST /api/sessions/plan` (пропозиція без збереження) · `POST /api/sessions` (старт) · `GET /api/sessions` · `GET /api/sessions/:id`

## Готово, коли

- Unit: побудова входу для планувальника з профілю й патернів; парсинг і Zod-валідація відповіді моделі.
- Інтеграційні: старт сесії без згоди → 403; зі згодою → сесія + перше питання.
- e2e: користувач із профілем → «Почати сесію» → бачить тему й питання → «Інша тема» → своя тема → старт → екран діалогу з першим питанням.
- Промпт планувальника — `packages/prompts/session-plan.v1.md`.
