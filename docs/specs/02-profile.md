# 02. Сценарій 1: онбординг і профіль

Гілка: `feat/02-profile`. Таблиці: `profiles`, `goals`.

## Поведінка

- Після згоди, якщо профілю немає, — онбординг із 3 кроків (один екран на крок, прогрес угорі):
  1. Рівень: A2 / B1 / B2 / C1, з коротким описом кожного українською.
  2. Сцени: множинний вибір із готових чипів (робота й мітинги, small talk, співбесіди, побут і сервіси, подорожі) + свій варіант.
  3. Цілі: 1–3 цілі вільним текстом, з підказками-прикладами («Вільно говорити на мітингах»).
- Екран профілю: перегляд і редагування рівня, сцен, цілей; позначити ціль виконаною (`status = done`); кнопка «Видалити акаунт» (з 01).
- Модель учня в профілі (поки лише читання): топ-5 патернів помилок за частотою і кількість слів за станами. Поки даних немає — порожній стан із поясненням.

## API

`GET /api/profile` · `PUT /api/profile` · `GET /api/goals` · `POST /api/goals` · `PATCH /api/goals/:id` · `DELETE /api/goals/:id` · `GET /api/profile/learner-model`

## Готово, коли

- Unit: валідація профілю (рівень лише з CHECK, сцени — непорожній масив, до 3 активних цілей).
- Інтеграційні: CRUD профілю й цілей; користувач не бачить і не змінює чужі цілі (404).
- e2e: новий користувач проходить онбординг → бачить профіль із введеними даними → змінює рівень → зміна збереглась після перезавантаження.
- Форми на react-hook-form + Zod-схеми з `packages/shared`; усі тексти в `uk.json`.
